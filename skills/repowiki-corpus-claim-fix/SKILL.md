# Fixing a generated architecture corpus (Tricipta `docs/architecture`)

`docs/architecture/<repo>/**.md` is GENERATED by `scripts/repowiki.py` (workspace repo `afed/tricipta`).
Editing page prose alone is both insufficient and unsafe — the generator rewrites pages wholesale.

## The generator's inputs (what you must also fix)

| Input | Where | Effect |
|---|---|---|
| `policy_notes[<repo>]` | `docs/architecture/_scope.json` | Injected into EVERY page prompt for that repo |
| page `brief` | `_scope.json` → `pages[]` | Passed verbatim as "What this page must cover" |
| page `source_files` | `_scope.json` | Grounding + drives staleness detection |
| briefs/policy origin | `<repo>/.qoder/repowiki/wiki_plan.yaml` (gitignored in each repo) | Re-read by `scope`, not by `generate` |

`generate` writes `dest.write_text(header + title + cite + body)` — full replacement, no merge.

## Case A — correcting a FALSE claim in a page

1. **Verify against the repo at the page's own anchor**, not current HEAD. The header's first line
   records `generated <date> · <repo>@<sha> · ...`; check that tree:
   `git -C ../tricipta-<repo> ls-tree -r --name-only <sha> -- <path>`.
2. **Search all three locations** for the claim — the page, the repo's policy notes, the page brief:
   ```bash
   grep -rn "<claim text>" docs/architecture/ | grep -v _scope.json
   python3 -c "import json;m=json.load(open('docs/architecture/_scope.json'))"  # inspect policy_notes + pages[].brief
   ```
3. **Fix the manifest first, page second.** Skipping the manifest means the next `generate`
   reintroduces the false text verbatim.
4. Re-run the gate.

Real case: pages asserted "there is no test suite — no `tests/` directory" while `tests/` (16 modules)
was tracked at the page's own anchor and CI ran `pytest -q`. The claim lived in two pages, one policy
note, and one brief. One paragraph had additionally dismissed the real `pytest` + scipy-guard CI steps as
"aspirational or stale relative to the current tree" — a generator rationalizing away contradicting evidence.
**Treat "X does not exist" / "this is stale" framing in these pages as a claim to verify, never as fact.**

## Case B — adding content that must survive regeneration

Editing the page shows the content now, but it is erased on the next sync of that page. Also append the
requirement to the page's `brief` in `_scope.json` — the brief is the only durable channel that makes the
generator reproduce the topic. Wording will not survive; the topic and `source_files` will.

```bash
python3 scripts/repowiki.py generate --repo <repo> --page "<page>" --dry-run   # calls nothing; confirms brief reaches the prompt
```

## Gate

```bash
python3 scripts/repowiki.py check --repo <repo>
```
Pass = `dead 0 · 0.0% OOB · OK`. Exit 2 = nothing to check.

**`check` does NOT re-run `quote_audit`/`path_audit`.** Those run only at generate time and are surfaced
from the page header's first line. So a hand-added ```` ```bash ```` block of commands cannot trip the
integrity gate — do not downgrade a section to prose "to be safe".

Cite the plot-api (or target) repo's own files with `#L` anchors — they resolve. A path outside that repo
(another sibling repo's `docker-compose.yml`) resolves as a DEAD citation and fails the gate (`--max-dead`
0); mention such cross-repo files as plain text instead.

## Scope discipline

A full-corpus `check` fails on OTHER repos (integrity flags, anchor lag) and is normal — `--repo <target>`
is the relevant signal. Do not rewrite pages from repos you were not asked to touch.
